# GridTalk 485 总线仿真器(结构体多实例版)

在 PC 上直接编译真实的 `../src/GridTalk.c`（协议已改为
`gridTalk_t` 结构体封装的多实例模式，一份代码任意实例数），通过
`txByte/nowUs/onRx/onSendResult` 钩子接入共享半双工总线模型，统计协议表现。

## 环境要求

- Windows + VS Build Tools（MSVC C++ 工具集，用于编译）
- PowerShell

## 构建与运行

```powershell
.\build_run.ps1                       # 默认: 120s, 每字节误码0.4%, 6台设备, 种子42, 9600bps, 不打包
.\build_run.ps1 -Duration 60 -Loss 0.4 -Devices 10 -Seed 42 -Baud 9600 -PacketMode 1 -PacketIdleMs 10
.\build_run.ps1 -Debug                # 附带协议层调试打印(状态机事件)
```

也可以手动运行编译好的 `sim.exe`：

```text
sim.exe [时长秒=120] [每字节误码率%=0.4] [设备数=6] [随机种子=42] [波特率=9600] [打包=0] [打包门限ms=10]
```

## 转发方式: 不打包 vs 打包

- **不打包(PacketMode=0, 默认)**: 字节随上线随投递, 接收方按本节点固有延时逐字节收到;
- **打包(PacketMode=1)**: 端到端整包——发送侧攒包期间字节**不上线**(模块立即收下,
  协议全速倾倒), 静默 `PacketIdleMs`(默认10ms)内无新字节后, 整包按字节节拍
  **突发上线**; 接收侧随突发连续收到完整一包(节点固有延时照常)。
  攒包期间总线静默, 别人侦听不到"正在攒包"的节点(盲区=门限), 由空闲保障窗
  (idleGuardUs, 打包模式自动=门限)随机化接入缓解; ACK窗口按
  `GT_ACK_WINDOW_CHARS*byteUs + 2*txDelayUs` 自动放宽(txDelay=门限+最大帧空中时间),
  避免大帧被误判超时重发。

## 仿真模型(物理层)

- 按配置波特率收发，字节上线时间 = 10bit / 波特率（9600bps 约 1.042ms）；
  仿真微步 = 字节时间的 1/10；
- **发送方启动抖动**：每帧首字节上线前附加 0~1字节时间 的随机延时
  （模拟UART启动/中断抖动，同时分散同刻起发的竞争），帧内后续字节
  由UART连续移位、无附加间隙；
- **接收方固有延时**：每个接收方在初始化时分配一个独立的随机小延时
  （0~1字节时间，节点固有），该节点收到的每个字节都延迟该时长投递，
  各节点观察到的字节到达时刻互不相同（顺序保持）；
- **无自回显**：字节不回投给发送方（协议的半双工回显过滤窗口空转，不影响协议）；
- **误码**：接收时每字节独立按配置概率（默认 0.4%）丢失或单比特翻转，
  帧内任何位置都可能损坏，长帧（如2KB回声分片约530字节）单帧完好率仅约12%；
- **字节级碰撞**：两字节上线时间重叠即碰撞，双方该字节作废，
  接收方采样到随机噪声字节；按帧vs帧/帧vs应答/应答vs应答分类统计；
- 每设备独立 tick 相位（模拟晶振漂移，避免完全同步）。

## 场景负载

- 设备A(索引0)：每100ms轮询ID 1..255（尽力而为探测），ID 1..N-1在线并回应；
- 设备B(索引1..N-1)：每5台一组，组内中继环 1->2->3->4->5->1，收到后延迟1秒转发
  （RELAY_FWD_DELAY_MS）。转发走响应帧通道无重发，令牌丢失即断环，
  组长检测环静默超过15秒（RELAY_REINIT_MS）自动重发令牌恢复；
- 设备C(最后一台)：每20秒向随机B发起一次2KB随机数据分片回声传输
  （5片x496B，带序号+校验+超时重发），检验大帧在误码下的可靠性；
- 报告输出：轮询发现情况、每组转发帧/完整圈数/圈耗时/单跳延迟、
  回声完成数/有效吞吐/分片RTT、总线利用率/碰撞分类/误码计数。

## 统计指标

- 总线利用率、字节级碰撞及分类（帧vs帧/帧vs应答/应答vs应答）；
- 误码：交付/丢失/改写字节数及合计误码率；
- 线上帧数/重发帧数/碰撞损坏帧数；
- 协议实测字节时间（自适应采样）与理论值对比；
- 每设备明细（线上帧/重发/转发ACK/收单播/单跳延迟）。

## 已知固件问题(本仿真器发现)

- **byteUs 自适应采样窗口 `0.5x~2x 当前值`**，锚定 `GT_DEFAULT_BYTE_US=1042`(9600bps)。
  波特率高于约19.2k时帧内间隙恒低于下限被拒，byteUs 永远停留在默认值，发送节流按12倍慢速运行
  （`-Baud 115200` 可复现：实测单字节时间=1042us, 理论=86us）。
  修复方向：按实际波特率初始化 byteUs（如编译期配置或首帧放宽采样下限）。
- **打包转发的对齐碰撞**: 攒包期间总线静默不可侦听(盲区=门限), 已由空闲保障窗
  (idleGuardUs, 打包模式自动=门限)随机化接入缓解; 剩余碰撞来自"两包同时到期突发"
  的对齐——9600bps/6台/0.4%误码下碰撞损坏帧约9%(旧"延迟投递"模型为26~30%)。
  进一步改善需转发设备暴露忙信号或对突发上线时刻加随机抖动。

## 调参结论(历史, 旧丢包模型下测得)

> 以下结论在旧模型（每帧2%首字节损坏、无启动抖动、有自回显）下测得，
> 新模型（每字节误码+收发抖动+无自回显）下需重新标定，仅作数量级参考。

| 配置 | 利用率 | 整帧碰撞/60s | ping送达 | ACK延迟avg |
|---|---|---|---|---|
| 优化前(帧间隔20ms/抖动500ms/超时1.5s) | 13% | ~30 | 80~92% | 866ms |
| 优化后(帧间隔3ms/抖动160ms/超时400ms+盲窗确认) | 27% | ~36~67 | 100% | 250~320ms |

- 9600bps/6台/0.4%每字节误码下，利用率约30~40%时轮询发现与中继环正常，
  碰撞损坏帧约2~3%；0误码配置下除碰撞外无丢失，2KB回声可完整传输。

## 可调参数(GridTalk.h)

- `GT_IDLE_CHARS_X10` 空闲判定(4.5字符)、`GT_AUTO_BACKOFF_CHARS` 自主帧随机退避、
  `GT_ACK_WINDOW_CHARS` ACK窗口(60字符, 下限250ms)、`GT_DEDUP_WINDOW_US` 去重窗口、
  `GT_TX_FIFO_SIZE` 发送缓存(8)、`GT_RESEND_COUNT` 重发次数(5)。

## 调试开关（环境变量）

- `GRIDTALK_TRACE=1`：打印指定设备的接收字节；
- `GRIDTALK_TRACE_DEV=N`：选择跟踪设备（0 基）；
- `GRIDTALK_BURSTLOG=1`：打印线上每一帧（burst）的内容；
- `-Debug` 构建：协议状态机事件打印（TX/ACK/JITTER/RETRY/GIVEUP/FIFO_DROP 等）。

## 与固件构建的关系

GridTalk.c 增加了两个测试接缝，固件构建不受影响：

- `GT_APP_PROVIDES_HOOKS`：定义后由应用提供 `GT_readData`/`GT_sendResult`
  （固件不定义该宏，仍使用库内弱函数）；
- `GT_UART_DR_WRITE(c)`：发送寄存器写抽象，默认展开为 `GT_UART->DR = (c)`，
  仿真时替换为 `sim_tx_byte(c)`。
